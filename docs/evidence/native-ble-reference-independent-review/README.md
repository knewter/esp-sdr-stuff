# Native BLE reference: independent prehardware review

The source, actual build002 artifact and bounded supervisor pass offline review for the prospective native observer diagnostic. This review opens no devices. It accepts the host/build prerequisites; it does not establish native reception, SDR decoding, transmitted-event counts or physical recovery for the new trial.

[Image checks](artifact-checks.json) independently recompute every part's size/hash, segment XOR checksum, appended image SHA256, exact ESP32 header/application descriptor, and partition-table MD5/layout. The three parts occupy only the declared bootloader, table and application ranges. Source bytes match both the recorded firmware commit `e2877280b0a97dd8e3feae419b58a18c9a960ef0` and current committed inputs. Generated observer/security policies and private permissions pass. The generated SDK compatibility section repeats 27 unrelated Wi-Fi keys with identical values; guarded native keys remain unique.

[Preflight checks](preflight-checks.json) identify the exact reviewed source hashes. Seven final supervisor regressions pass independently, including a dead Task leader with a still-running restoration group, timeout without forced termination, partial READY lines, and malformed HCI receipts. The supervisor waits for natural closure of the whole native process group. It closes the source and monitor first and leaves a timed-out native group running rather than starting competing restoration. Source admission requires nonce-matched scan readiness and monitor readiness, an initial ten-second OFF interval, exact actual HCI settings and 15 successful command completions. Completion requires an actual END receipt more than ten seconds after source-group closure and verified recovery.

The first native build's missing privacy/security symbols remain a failed build with no installable artifact. On this original ESP32, the pinned SDK forces host privacy despite the requested privacy options; disabling connection roles removes its AES helper definition. The application supplies the same reversed-byte AES-128 primitive through PSA, with error handling, imported-key cleanup and alias-safe output. The SDK source stays unchanged. The boot known-answer self-test runs before NimBLE initialization or CONFIG; its target execution remains a physical-trial prerequisite.

The real mbedTLS PSA Nix derivation passes all 21 native tests without skips, including the known-answer and input/key/output alias cases. The independent reviewer reran `nix develop .#ci --command task native:ble:crypto-check`, inspected both successful derivation logs, and checked the locked dependency/Task integration. Mock-PSA cases additionally exercise failures without publishing partial output. The AES vector is from [NIST FIPS 197 (2001), Appendix C.1](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.197.pdf); byte-order semantics match the [pinned Espressif NimBLE helper](https://github.com/espressif/esp-nimble/blob/1a714b03dcea55e58066e21213a5f150f2e50088/nimble/host/src/ble_sm_alg.c#L118). The forced privacy definitions are in the [pinned SDK](https://github.com/espressif/esp-idf/blob/25fe69f946311abdaf9ad56591f25fedbc20ac98/components/bt/host/nimble/port/include/esp_nimble_cfg.h#L964).

The app performs a finite passive scan, matches the complete owned AD, and publishes only aggregate counts/RSSI and fixed typed fields. Foreign payloads and addresses remain absent from its public protocol. The host distinguishes received UART bytes from actually persisted bytes, retains storage failures honestly, and rejects restarted, out-of-sequence, inconsistent or incomplete observations. The separate native artifact allowlist leaves the SDR firmware policy unchanged. Raw UART, firmware images and execution snapshots stay private and ignored.

UART JSON has no transport CRC. Schema/nonce/cumulative validation and saved-byte hashes do not replay protected BLE PDU CRC or provide a transmitted-event denominator. Controller report counts can include duplicates and scans across multiple advertising channels. Aggregate device intervals and full host-line brackets must be retained; UART receipt time does not identify individual RF emission time. Phase joins require conservative boundary exclusions and explicit clock/latency uncertainty. A native positive can guide a later receiver experiment; it cannot pass the existing SDR or counted-emission gates. A null remains inconclusive.

Actual target boot, complete scan/source/monitor receipts, process closure, full original-flash readback and known boot behavior require a separate physical review. The existing RF, counted-burst and FPGA gates remain unchanged.

## First physical attempt: failure retained

[Independent trial001 checks](trial-001-checks.json) reparse the complete private UART log: 23,986 bytes, 92 consecutive contiguous aggregates, interval sums equal the final cumulative 1,160 exact-owned controller reports, and no END. The last aggregate extends to 92.902916 seconds; the app emits `ERROR SCAN_TIMEOUT/-1`. Successful CONFIG/READY occurs after the target crypto self-test, but the finite scan terminal requirement fails. This is a retained failed reference with meaningful reception observations, not a completed 90-second reference.

The actual source has three episodes and 15 successful HCI command completions. Independent hashes of both before-install and restored full 4 MiB files equal the preserved original `6e8f0793916fa1d701415abc48c6ea91756cf864de8fdbf8459c181b08fc0974`. The recovery receipt verifies the original boot checks. All child groups, source bus and monitor container close; the supervisor correctly remains failed.

The [pinned host timer handler](https://github.com/espressif/esp-nimble/blob/1a714b03dcea55e58066e21213a5f150f2e50088/nimble/host/src/ble_hs.c#L571) dispatches `ble_gap_timer()` only when `NIMBLE_BLE_CONNECT` is enabled. Both connection roles are disabled in this observer-only build. The [discovery implementation](https://github.com/espressif/esp-nimble/blob/1a714b03dcea55e58066e21213a5f150f2e50088/nimble/host/src/ble_gap.c#L8372) converts the supplied milliseconds correctly and schedules the deadline, but the guarded host handler does not service that GAP timer. This source-level defect explains the absent natural completion under the actual configuration; it is not a duration-unit error.

A prospective v2 may deliberately stop scanning at the application deadline using the public API. [Apache's GAP contract](https://mynewt.apache.org/latest/network/ble_hs/ble_gap.html#c.ble_gap_disc_cancel) defines successful cancellation as fully aborted scanning. In the pinned source, cancellation holds the host mutex, sends scan-disable, waits for the matching HCI acknowledgement/status, and resets discovery state only after success. It emits no natural DISC_COMPLETE callback. A new protocol must therefore require an actual cancellation return of zero, inactive discovery, explicit `completion_mode=application_cancel`, bounded monotonic duration and immutable terminal counts. Failed or premature stopping must fail. This route needs a fresh version/config/artifact review and physical trial; it does not retroactively repair trial001 or change the SDR/RF/count gates.
